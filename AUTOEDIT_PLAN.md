# AutoEdit — план программы автомонтажа

Этот файл — предварительный план (без кода) для программы **AutoEdit**,
которая должна собирать черновой монтаж документальных YouTube-роликов
по готовому монтажному плану (`plan.json`). Написан по итогам разговора
о том, как это делает профессиональный монтажёр, и что из этого может
взять на себя программа.

> Примечание про среду: этот план временно лежит в репозитории
> `hello-first-pr`, так как отдельный репозиторий `autoedit` создать
> не удалось (у GitHub-приложения Claude нет прав на создание новых
> репозиториев). Когда репозиторий `autoedit` появится — весь код и
> этот план стоит перенести туда.
>
> Также: облачная среда, где работает Claude Code, — это временный
> контейнер без FFmpeg и без ваших реальных видеофайлов. Реальный рендер
> на ваших ассетах и в CapCut/DaVinci будет выполняться у вас на
> компьютере; здесь код можно только написать и проверить на демо-данных
> (`autoedit demo`).

---

## 1. Принцип

Программа не принимает творческих решений. Все решения (какой кадр,
где склейка, где тишина, какой звук) уже записаны в `plan.json`.
Программа точно исполняет план и обо всех проблемах честно сообщает
в отчёте — по-русски и с понятной подсказкой, что делать.

## 2. Взгляд монтажёра (этап 0)

**Как монтажёр собирает ролик:**
1. Слушает начитку целиком, размечает биты сцены: подготовка → фокус →
   пауза → раскрытие → последствие.
2. Подбирает кадр под смысл фразы, а не под секунды.
3. Строит J-cut/L-cut — звук следующей (или предыдущей) сцены заходит
   раньше (или задерживается) относительно картинки.
4. Держит один смысловой акцент на кадр; ритm рваный, не метрономом.
5. Ведёт музыку по главам, приглушает под голос, обрывает перед важным
   моментом и возвращает после.

**Что обязана уметь программа**, чтобы черновик не стыдно показать:
- точная привязка кадров к словам диктора (anchor);
- J-cut и L-cut;
- «ручки» (handles) на исходниках, чтобы переходы не упирались в край;
- плавный zoom/pan без дрожания;
- тишина/пауза как явное событие плана, а не побочный эффект;
- отчёт, где у каждого решения есть причина (`why`) из плана.

**Что лучше оставить человеку:**
- сам монтажный замысел (что где стоит, `plan.json` пишет человек или
  отдельный инструмент);
- финальную полировку темпа и мелкие ручные правки;
- творческие акценты, которых нет в плане.

**Типичные «машинные» ошибки автомонтажа и как программа их не допускает:**

| Ошибка | Защита в программе |
|---|---|
| Склейка посреди слова | Якоря ищутся по границам слов (`faster-whisper` + fuzzy-поиск фраз) |
| Слайдшоу из одной картинки | Поле `crop` — разные планы с одной картинки; параллакс для слоёв фон/персонаж |
| Одинаковый ритм (склейка каждые N сек) | Длительность кадра только из плана, программа её не выравнивает |
| Музыка громче голоса | Sidechain-приглушение музыки под голос + проверка в отчёте |
| Резкие обрывы звука | Обязательные fade на границах музыки и эффектов |
| Хаотичное направление движения камеры | `motion` берётся из плана, ease-in-out, без автоподбора |

## 3. Формат `plan.json` — предлагаемые доработки

К исходному формату (единый план на ролик, кадры со ссылкой на anchor,
секции `music`, `end_screen`) монтажёр предлагает добавить:

- **`audio_lag`** (число, сек) — симметрично `audio_lead`: для L-cut,
  когда звук *предыдущей* сцены остаётся звучать после смены картинки.
- **`handles`** (число, сек, по умолчанию из настроек проекта) — запас
  по каждой стороне исходника, который нельзя трогать переходом/кропом.
- **`min_ai_visible_seconds`** — явное разрешение монтажёра на долгий
  ИИ-кадр без предупреждения "кадр длиннее 8 сек" в отчёте (отличается
  от `allow_long`, который просто снимает предупреждение о длине; этот
  параметр ещё и не считается "разгоном" одного и того же ИИ-клипа во
  время подсчёта доли ИИ-визуала).
- Валидация плана должна проверять: файлы существуют, anchor находится
  в озвучке (и по порядку), сумма `audio_lead`/`audio_lag` не вылезает
  за пределы соседних кадров, `crop` не выходит за границы кадра.

Остальной формат (пример из исходного запроса: `shots[]` с `anchor`,
`asset`, `motion`, `transition_in`, `overlays`, `sfx`, `beat`, `chapter`,
блок `music` с `from_anchor`/`to_anchor`, `end_screen`) сохраняется как
есть.

| 2 | Привязка к голосу: `faster-whisper` с таймкодами слов, нечёткий поиск anchor-фраз по порядку, кэш в `alignment.json`, генерация `subtitles.srt`. | ✅ сделано |

| 4 | Звук: слои голос/музыка/фон/эффекты, нормализация и компрессия голоса, sidechain музыки под голос, `silence_before`, эффекты по `offset`, финальный loudnorm (−14 LUFS, −1 dBTP). | ✅ сделано |
| 5 | Рендер и отчёт: `--final`/черновик, рендер по кускам с кэшем по хэшу параметров кадра, прогресс, `report.txt` со всеми проверками монтажёра, три режима проверки (`--check-no-fx`, `--check-no-sound`, `--check-audio-only`). | ✅ сделано |
| 6 | Экспорт таймлайна через OpenTimelineIO в FCPXML/OTIO для DaVinci Resolve (CapCut — закрытый формат, экспорт под него не делаем). | ✅ сделано |

## 5. Что стоит знать перед реальным использованием

1. **Репозиторий.** Код временно живёт в `hello-first-pr` — отдельный
   репозиторий `autoedit` создать не удалось (у GitHub-приложения
   Claude нет прав на создание репозиториев). Стоит перенести код в
   отдельный репозиторий, когда он появится.
2. **Распознавание речи не проверялось на реальной озвучке.** Модель
   `faster-whisper` скачивается с Hugging Face — облачная песочница,
   где писался код, блокирует этот хост политикой сети, поэтому логика
   привязки anchor-фраз и генерации субтитров проверена юнит-тестами на
   синтетических транскриптах и явным моком загрузки модели, а не на
   реальном распознавании речи. Обязательно проверьте `autoedit check`
   на своём реальном проекте с озвучкой.
3. **Видео/звук/экспорт таймлайна проверены сквозным рендером** демо-
   проекта настоящим FFmpeg (он был установлен в песочнице специально
   для тестирования) — все режимы (`--final` и три `--check-*`)
   отработали корректно на цветных заглушках.
4. **GUI (этап 7) не тестировался** — в песочнице, где писался код, не
   удалось собрать `tkinter` для нужной версии Python. Код написан по
   стандартной документации `tkinter`, но при первом запуске
   `autoedit gui` возможны мелкие шероховатости.
