# AutoEdit

Программа для чернового автомонтажа документальных YouTube-роликов по
готовому монтажному плану (`plan.json`). Программа не принимает
творческих решений — она точно исполняет план и сообщает о проблемах.

Общий план проекта и рассуждения монтажёра — в файле
[`../AUTOEDIT_PLAN.md`](../AUTOEDIT_PLAN.md).

## Что умеет программа

- `autoedit check <папка_проекта>` — проверяет `plan.json` и все файлы,
  на которые он ссылается (включая привязку anchor-фраз к озвучке),
  печатает ошибки/предупреждения, сохраняет отчёт и `subtitles.srt`.
- `autoedit demo [папка]` — создаёт тестовый проект с фальшивыми
  ассетами (цветные заглушки вместо видео, тон вместо голоса) и
  небольшим `plan.json`, чтобы проверить программу без ваших реальных
  файлов.
- `autoedit render <папка_проекта>` — собирает ролик: находит тайминги
  по озвучке, рендерит каждый кадр (движение камеры, переходы, оверлеи
  на хромакее, текст), сводит звук (голос + музыка с автоматическим
  приглушением под голос + эффекты, мастеринг громкости под YouTube),
  экспортирует таймлайн для DaVinci Resolve и пишет подробный отчёт.
  По умолчанию — черновик (`--final` — финальное качество). Флаги
  `--check-no-fx` / `--check-no-sound` / `--check-audio-only` собирают
  ролик в одном из трёх «честных» проверочных режимов монтажёра.
- `autoedit gui` — необязательное простое окно (папка проекта, кнопки
  «Проверить/Черновик/Финал», лог, кнопка «Открыть отчёт»). Нужен
  `tkinter` в вашей установке Python (в официальных сборках с
  python.org для Windows/macOS он есть по умолчанию).

## Установка

1. Нужен **Python 3.11 или новее**. Проверить версию:
   ```
   python3 --version
   ```
2. Нужен **FFmpeg** — программа для работы с видео и звуком. Команда
   `autoedit check`/`autoedit render` сама проверяет, установлен ли
   он, и подсказывает команду для вашей операционной системы (macOS —
   Homebrew, Windows — winget, Linux — apt или аналог вашего
   дистрибутива).
3. Установите саму программу (из корня репозитория):
   ```
   pip install -e .
   ```
   Это ставит Python-зависимость `faster-whisper` (распознавание речи)
   и делает команду `autoedit` доступной в терминале. Флаг `-e`
   означает, что изменения в коде сразу подхватываются без
   переустановки.

   Экспорт таймлайна для DaVinci Resolve (этап 6, необязательно)
   ставится отдельно:
   ```
   pip install -e .[export]
   ```
   На некоторых системах (например, очень новая версия Python, для
   которой ещё нет готовых пакетов) эта установка может упасть с
   ошибкой сборки (`CMake Error... CMAKE_C_COMPILER not set` и
   похожими) — для сборки из исходников нужен установленный компилятор
   C++, которого обычно нет на обычном компьютере. Это не страшно:
   `autoedit check`/`autoedit render` прекрасно работают и без этого,
   просто не будет файлов `timeline.otio`/`timeline.fcpxml` (программа
   один раз предупредит об этом и продолжит работу). Если экспорт
   всё же нужен, самый надёжный способ — поставить рядом отдельную,
   более "обычную" версию Python (например 3.12) через `winget install
   Python.Python.3.12` и запускать `autoedit` через неё.

   При первом запуске `autoedit check`/`autoedit render` на проекте с
   озвучкой модель распознавания речи скачивается один раз из
   интернета (Hugging Face, обычно от ~150 МБ для модели `small`) и
   дальше работает офлайн. Если скачать не получилось (нет интернета
   или он заблокирован), программа не упадёт — она предупредит об этом
   и продолжит работу с кадрами, заданными явными `start`/`duration`
   (без anchor-кадров и без `subtitles.srt`).

## Быстрая проверка на демо-проекте

```
autoedit demo
autoedit check ./autoedit_demo_project
autoedit render ./autoedit_demo_project
```

Первая команда создаст папку `autoedit_demo_project` с фальшивыми
файлами и планом (без anchor-кадров — там нечего распознавать).
Вторая проверит план. Третья соберёт черновой ролик
`autoedit_demo_project/output/preview.mp4`. Так можно убедиться, что
всё работает, не трогая ваши реальные материалы.

## Работа со своим проектом

Разложите проект в такую структуру:

```
project/
  plan.json
  voice/               озвучка (mp3/wav)
  assets/ai/           ИИ-клипы и картинки
  assets/stock/        стоковые видео
  assets/graphics/     графика (mp4, png), в т.ч. *_greenscreen.mp4
  assets/maps/         пролёты Google Earth
  assets/sfx/          звуковые эффекты
  assets/music/        музыка
  lut/                 необязательно: цветовой LUT (.cube)
```

Сначала проверьте план:

```
autoedit check project/
```

Когда ошибок нет — соберите черновик, посмотрите, и при необходимости
финал:

```
autoedit render project/
autoedit render project/ --final
```

Результат — в `project/output/`: `preview.mp4`/`final.mp4`,
`subtitles.srt`, `report.txt`, `timeline.otio` и `timeline.fcpxml`
(открываются в DaVinci Resolve; CapCut использует закрытый формат
проектов — экспорт под него не делается, пересобирайте ролик там
вручную по отчёту и готовому видео как референсу).

### Три проверочных режима

Чтобы понять, держится ли история сама по себе:

```
autoedit render project/ --check-no-fx      # без эффектов и графики
autoedit render project/ --check-no-sound   # без звука
autoedit render project/ --check-audio-only # только звук (файл .wav)
```

## Формат plan.json

```json
{
  "title": "438 Days",
  "voice": ["voice/full.mp3"],
  "look": { "lut": "lut/doc.cube", "grain": 0.3, "vignette": 0.4 },
  "shots": [
    {
      "id": "H01",
      "anchor": "Imagine leaving home",
      "asset": "assets/ai/I1_boat_leaving.mp4",
      "motion": "zoom_in",
      "motion_amount": 0.08,
      "source_start": 0.0,
      "transition_in": "cut",
      "transition_duration": 0.5,
      "overlays": [
        { "asset": "assets/graphics/G9_date_greenscreen.mp4", "chroma_key": "#00FF00", "offset": 0.3 }
      ],
      "text": null,
      "sfx": [ { "asset": "assets/sfx/ocean_waves.wav", "offset": 0.0, "volume": 0.15 } ],
      "is_ai": true,
      "why": "открываем с обложки: зритель видит, что попал куда нужно",
      "beat": "preparation",
      "chapter": "Intro",
      "audio_lead": 0.0,
      "audio_lag": 0.0,
      "crop": null,
      "silence_before": 0.0,
      "handles": 0.5,
      "allow_long": false,
      "min_ai_visible_seconds": 0.0
    }
  ],
  "music": [
    { "asset": "assets/music/tension.mp3", "from_anchor": "Imagine leaving home",
      "to_anchor": "They accuse you", "volume": 0.18, "fade_out": 0.3 }
  ],
  "end_screen": { "asset": "assets/graphics/end_screen.mp4", "duration": 20 }
}
```

Основные правила:

- Время кадра задаётся либо через `"anchor"` (привязка к словам
  диктора — ищется нечётким поиском по озвучке, по порядку), либо явно
  через `"start"` и `"duration"` (в секундах, для мест без голоса).
  Длительность anchor-кадра, если не задана явно, — это время до
  начала следующего кадра.
- Допустимые значения `motion`: `zoom_in`, `zoom_out`, `pan_left`,
  `pan_right`, `rise`, `static`. Движение всегда плавное (ease-in-out).
- Допустимые значения `transition_in`: `cut`, `crossfade`,
  `fade_from_black`.
- Допустимые значения `beat`: `preparation`, `focus`, `pause`,
  `reveal`, `consequence` (пока не влияют на рендер — это разметка для
  человека и будущих проверок монтажёра).
- `crop: [x, y, w, h]` (доли кадра 0..1) — второй план из той же
  картинки/клипа без слайдшоу.
- `audio_lead` — J-cut (звук кадра начинается раньше картинки);
  `audio_lag` — L-cut (звук предыдущего кадра остаётся после смены
  картинки). *В текущей версии это поля разметки для монтажёра/OTIO —
  рендер аудио пока не сдвигает звук кадра по ним отдельно от голоса.*
- `silence_before` — на сколько секунд выключить музыку перед этим
  кадром.
- `handles` — запас в секундах по краям исходника для переходов (поле
  разметки, использует экспорт в OTIO/FCPXML).
- `why` — причина решения; попадает в `report.txt`.
- Музыка приглушается автоматически под голос (sidechain-компрессия) —
  вручную балансировать громкость не нужно.
- Итоговая громкость всегда мастерится под YouTube: −14 LUFS, true
  peak −1 dBTP.

## Частые ошибки

- **«Файл плана не найден»** — в указанной папке нет `plan.json`.
- **«план... повреждён (невалидный JSON)»** — опечатка в файле
  (лишняя/пропущенная запятая или кавычка); в сообщении указаны строка
  и столбец.
- **«Кадр X: файл не найден»** — путь к ассету не совпадает с реальным
  расположением. Пути в плане — относительно папки проекта.
- **«слова "..." не найдены в озвучке»** — anchor-фраза не найдена (или
  найдена не по порядку) в распознанном тексте. Проверьте точность
  формулировки и совпадение с озвучкой.
- **«FFmpeg: НЕ найден»** — установите FFmpeg по подсказке в консоли.
- **«привязка к озвучке пропущена: ... 403/timeout»** — не удалось
  скачать модель распознавания речи (нет интернета в момент первого
  запуска). Повторите с интернетом или продолжайте с явными
  `start`/`duration` в плане.
- **«клип короче нужной длительности даже при замедлении»** —
  исходный файл слишком короткий для нужного кадра даже после
  замедления до 0.8×; последний кадр удерживается (freeze-frame),
  в отчёте это отмечено — стоит подобрать более длинный исходник.

## Тесты

```
python -m unittest discover -s tests
```

Тесты, которым нужен реальный рендер, автоматически пропускаются, если
в системе не установлен FFmpeg. Реальная работа `faster-whisper`
(скачивание и запуск модели) не тестируется автоматически — это
внешняя ML-модель; проверьте её на своём проекте командой `autoedit
check`.
