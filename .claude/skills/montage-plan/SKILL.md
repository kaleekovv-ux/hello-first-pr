# Монтажный план для AutoEdit

Творческие решения принимаешь ты (программа их не принимает) — каждое записывай в поле `why`.
Полный список полей с пояснениями — `plan_example.txt` в корне репозитория; не дублируй его, а читай при необходимости.

## Что попросить у пользователя
1. `script.txt` — сценарий, по фразе на строку (тот же, что для `autoedit voice`).
2. Список ассетов: вывод `dir /s /b assets` из папки проекта (PowerShell) — пути пиши относительно папки проекта.
3. По возможности — `contact_sheet.jpg` из `autoedit sheet assets` (чтобы видеть, что в кадре).
4. Если озвучка уже распознана — `output/subtitles.srt`: anchor-фразы бери оттуда дословно.

## Структура документального ролика
- **Хук (0–15 сек)**: самый сильный факт/образ раньше объяснений. Короткие кадры 1.5–3 сек.
- **Завязка**: кто, где, когда. Карта/архив, спокойнее (3–5 сек на кадр).
- **Главы** (`chapter`): у каждой своя музыка и арка битов `preparation → focus → pause → reveal → consequence` (поле `beat`).
- **Развязка и финал**: последствие, тишина или музыка на спаде, `end_screen`.

## Правила монтажа (их проверяет report.txt)
- Кадр не длиннее 8 сек; если осознанно дольше — `"allow_long": true` и объяснение в `why`.
- ИИ-кадры (`is_ai: true`) — не больше 30% экранного времени; один ИИ-клип не повторять — нужен другой план той же картинки через `crop`.
- Один смысловой акцент на кадр; ритм неровный — не ставь кадры одинаковой длины подряд.
- Перед `reveal` — `"silence_before": 0.5..1.0` (музыка стихает) и часто `transition_in: "fade_from_black"`.
- `motion` выбирай по смыслу: `zoom_in` — напряжение/фокус, `zoom_out` — масштаб/одиночество, `pan_*` — путь/пространство, `rise` — надежда, `static` — факт/документ. Не чередуй направления хаотично.
- Текст на экране (`text`) — только цифры и короткие факты, ≤ 6–7 слов, `highlight` на главном числе.
- Музыка: трек на главу, `fade_in` 1–2 сек, `fade_out` 2 сек, громкость 0.12–0.2 (под голос приглушается сама).
- Не используй `audio_lead`, `audio_lag`, `handles` в расчёте на эффект — программа их пока не применяет.

## Anchor-фразы (главный источник ошибок)
- 3–6 слов, дословно как звучит в озвучке (лучше — скопировать из `subtitles.srt`).
- Уникальные: не бери фразы, которые повторяются в тексте («and then», «но»).
- Кадры с anchor идут в plan.json строго в порядке звучания. Поиск идёт только вперёд: если один anchor совпал не там, следующие «не найдутся» — исправляй первый из упавших или предыдущий перед ним.
- Числа: whisper часто пишет их словами — в anchor пиши так, как в `subtitles.srt`.
- Нет озвучки или кадр вне речи (заставка) — используй `start` + `duration` вместо `anchor`.

## Порядок работы
1. Разбей сценарий на главы и биты, отметь хук и места для тишины.
2. Для каждой фразы-смены картинки выбери ассет и anchor; заполни `why`, `beat`, `chapter`, `is_ai`.
3. Проверь долю ИИ и длины кадров в уме, затем отдай пользователю готовый `plan.json` целиком (валидный JSON, без комментариев).
4. Пользователь запускает `autoedit check .` и присылает вывод — исправляй по сообщениям (они говорят, с какой секунды шёл поиск anchor).
5. Затем `autoedit build .`.
