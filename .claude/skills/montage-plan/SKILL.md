# Монтажный план для AutoEdit

Творческие решения принимаешь ты (программа их не принимает) — каждое записывай в поле `why`.
Сначала прочитай `lessons.md` рядом с этим файлом (уроки прошлых роликов) и, если есть, примеры пользователя в `examples/*.json` — делай в его стиле.
Полный список полей — `plan_example.txt` в корне репозитория; читай только при необходимости.

## Что попросить у пользователя
1. Вывод `autoedit draft . --script script.txt` — готовый `plan_draft.json` (кадры по фразам, anchor уже проверены по озвучке). Это главный вход: не пиши anchor-ы сам, если черновик есть.
2. Список ассетов: `dir /s /b assets` из папки проекта.
3. По возможности — `contact_sheet.jpg` из `autoedit sheet assets`.

## Структура документального ролика
- **Хук (0–15 сек)**: самый сильный факт/образ раньше объяснений. Короткие кадры 1.5–3 сек.
- **Завязка**: кто, где, когда. Карта/архив, спокойнее (3–5 сек на кадр).
- **Главы** (`chapter`): у каждой своя музыка и арка битов `preparation → focus → pause → reveal → consequence` (поле `beat`).
- **Развязка и финал**: последствие, тишина или музыка на спаде, `end_screen`.

## Правила монтажа (их проверяет report.txt)
- Кадр не длиннее 8 сек (draft уже делит длинные фразы); дольше — только с `"allow_long": true` и объяснением в `why`.
- ИИ-кадры (`is_ai: true`) — не больше 30% экранного времени; один ИИ-клип не повторять — другой план той же картинки через `crop`.
- Один смысловой акцент на кадр; ритм неровный — не ставь кадры одинаковой длины подряд.
- Перед `reveal` — `"silence_before": 0.5..1.0` и часто `transition_in: "fade_from_black"`.
- `motion` по смыслу: `zoom_in` — напряжение/фокус, `zoom_out` — масштаб/одиночество, `pan_*` — путь/пространство, `rise` — надежда, `static` — факт/документ.
- Текст на экране (`text`) — только цифры и короткие факты, ≤ 6–7 слов, `highlight` на главном числе.
- Музыка: трек на главу, `fade_in` 1–2 сек, `fade_out` 2 сек, громкость 0.12–0.2.

## Сдвиг склейки относительно слов (J-cut / L-cut)
- `"audio_lead": 0.3..0.8` — фраза начинает звучать, картинка меняется чуть позже («сначала слышим, потом видим»): плавный переход между сценами, нагнетание. На первом кадре — голос начинается на чёрном экране.
- `"audio_lag": 0.3..0.8` — картинка меняется чуть раньше фразы («сначала видим, потом слышим»): показать место/предмет до того, как диктор его назовёт.
- Не больше чем на 2–3 склейках из 10, иначе ритм размывается. Звуки `sfx` и `silence_before` остаются привязаны к словам, сдвигается только картинка.
- `handles` и `min_ai_visible_seconds` программа пока не применяет — не используй.

## Anchor-фразы
- Если есть `plan_draft.json` — бери anchor-ы оттуда как есть (они дословно из распознанной озвучки и проверены).
- Если пишешь сам: 3–6 слов дословно из `output/subtitles.srt`, уникальные, кадры строго в порядке звучания.
- Поиск идёт только вперёд: если anchor «не найден», причина часто в предыдущем anchor-е — сообщение `check` показывает, с какой секунды шёл поиск.
- Удалил или переставил кадры из черновика — обязательно перезапусти `autoedit check .`.

## Порядок работы
1. Прочитай `lessons.md`, примеры, `plan_draft.json`.
2. Разметь главы и биты, отметь хук и места для тишины.
3. Заполни для каждого кадра `asset`, `why`, `motion`, `beat`, `chapter`, `is_ai`; объединяй слишком короткие соседние кадры (< 1.5 сек) одной картинкой. Поле `line` можно оставить — программа его игнорирует.
4. Проверь долю ИИ и длины кадров, отдай пользователю `plan.json` целиком (валидный JSON).
5. Пользователь запускает `autoedit check .` → исправляй по сообщениям → `autoedit build .`.
6. После ролика спроси, что понравилось/не понравилось, и допиши 1–3 коротких урока в `lessons.md`.
